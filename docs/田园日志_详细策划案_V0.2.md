# 《田园日志》详细游戏策划案 V0.2

**文档性质：** 单机纯文字农牧场养成游戏开发规格书  
**目标平台：** PC Web / Windows / macOS  
**核心模式：** 现实日驱动的压缩历法  
**版本日期：** 2026-08-12  
**文档状态：** 可用于原型开发、内容生产与首轮数值验证

## 0. 版本说明与阅读方式

### 0.1 本版完成的调整

- 删除此前大纲中的商业化与发行方案内容。
- 将“可扩展迭代”提升为底层设计约束：系统、内容、存档和随机数均按可扩展方式定义。
- 从概念大纲扩展为开发规格书，按系统说明目标、规则、状态、公式、边界、扩展点和验收标准。
- 给出首版作物、动物、加工、建筑、天气、成长和经济数值。
- 对首季现金流、压力场景、动物回本周期、加工增值和每日工时负载进行可复算验算。

### 0.2 需求优先级定义

| 等级 | 含义 | 开发处理 |
|---|---|---|
| P0 | 核心闭环或存档安全 | 原型必须实现，不得以内容替代 |
| P1 | 完整体验所需 | 春季体验版必须实现 |
| P2 | 正式版丰富度 | 完整四季前实现 |
| EXT | 已保留接口的后续能力 | 不阻塞首版，但不得破坏扩展接口 |

### 0.3 系统章节统一模板

每个系统尽量按照“目标—依赖—状态—规则—公式—边界—扩展点—验收标准”描述。标有 `ID` 的对象必须使用稳定英文标识，显示名称通过本地化表读取，不把中文名称作为存档主键。

## 1. 产品定义

### 1.1 一句话定位

一款适合上班或学习间隙打开的单机纯文字农牧场养成游戏：每个现实日生成一页新的牧场生活，基础劳作自动执行，玩家把时间用于经营选择、异常处理和人物故事。

### 1.2 核心体验支柱

1. **低压力持续生活。** 不登录不会导致动物死亡、主要剧情永久错过或农场不可逆崩坏。
2. **有选择的经营。** 玩家决定种什么、养什么、加工什么、把有限工时用在哪里，而不是逐格浇水。
3. **有记忆的文字世界。** 动物、居民、土地和日志记录过去选择，并在数日或数季后反馈。
4. **低调而清晰。** 无图片、无动画、默认无声音；界面像简洁的日志或内部管理系统。
5. **长期可扩展。** 新作物、新动物、新天气、新事件和新系统能够分批加入，并兼容旧存档。

### 1.3 目标游玩时长

| 内容层 | 正常耗时 | 是否必须当日完成 | 组成 |
|---|---:|---|---|
| 今日核心 | 8—15分钟 | 否；可由托管完成基础部分 | 日报、异常、工作安排、一个主要决定 |
| 今日可选 | 15—35分钟 | 否；多数可暂存3—7日 | 小镇通信、委托、探索、加工规划、关系事件 |
| 深度整理 | 10—20分钟 | 否 | 账目、日志、田区方案、仓库与长期建设 |
| 每日总量 | 30—60分钟 | 允许分多次完成 | 达到上限后不再堆叠高价值必做内容 |

### 1.4 首版明确边界

- 单机、本地存档，不含玩家之间的任何互动。
- 纯文字和标准界面控件，不使用场景图、角色立绘、动画或强制音频。
- 不做实时走路、逐格地图、即时战斗和依赖反应速度的小游戏。
- 第一阶段不做结婚、生子、复杂遗传、坐骑和大型矿洞；接口保留，后续按模块接入。
- 第一年结束后生成阶段总结，但存档可以继续经营，不设置强制失败结局。

## 2. 可扩展架构总则（P0）

### 2.1 四层架构

| 层级 | 职责 | 不应承担的职责 |
|---|---|---|
| 表现层 Presentation | 纯文字页面、快捷键、筛选、日志格式 | 不直接修改经济或实体状态 |
| 规则层 Rules | 公式、状态机、条件判断、效果执行 | 不保存界面临时状态 |
| 内容层 Content | 作物、天气、动物、事件、配方、居民配置 | 不写不可迁移的硬编码分支 |
| 状态层 State | 存档实体、日期、库存、历史和版本信息 | 不复制整份当前配置表 |

表现层只能发送语义命令，例如 `plan.assign`、`crop.harvest`、`event.choose`。规则层返回结构化结果和日志键，页面不得直接执行“资金 +100”一类操作。

### 2.2 稳定 ID 与版本

- 所有内容对象使用稳定 ID，例如 `crop_turnip`、`weather_light_rain`、`event_cow_bloat_01`。
- 配置文件包含 `schema_version`；内容包包含 `content_version`；存档包含 `save_version`。
- 已上线 ID 不复用。删除内容时标记 `deprecated` 并提供替代或安全清理规则。
- 数值调整只改配置；语义变化需要提升 schema 版本并添加迁移器。
- 存档保存“实体状态＋内容 ID＋必要快照”。影响已发生交易的历史价格写入日志快照，避免更新后旧账变化。

### 2.3 数据驱动扩展等级

| 新内容 | 理想改动范围 | 是否需要程序代码 |
|---|---|---|
| 新作物 | 新增作物行、本地化、掉落/配方引用 | 标准生命周期不需要 |
| 新天气 | 新增天气定义、季节权重和标签效果 | 使用现有效果词汇时不需要 |
| 新事件 | 新增条件、文本、选项和效果配置 | 使用现有条件/效果时不需要 |
| 新配方 | 新增输入、输出、设备、耗时配置 | 不需要 |
| 新居民 | 新增居民状态、日程标签和事件链 | 通常不需要 |
| 标准动物 | 新增物种、产品、饲料和生命周期 | 通常不需要 |
| 独特系统 | 注册系统命名空间、命令、存档迁移 | 需要，但不得改写其他系统核心状态 |

### 2.4 条件与效果词汇

事件和内容配置使用白名单表达式，不直接执行脚本。首版至少支持：

- 条件：日期、季节、天气标签、资金范围、物品数量、建筑等级、技能等级、关系值、实体状态、历史标记、事件冷却。
- 效果：增减资金/物品/工时/状态，添加标记，安排后续事件，修改关系，创建订单，启动建设，写入日志。
- 组合：`all`、`any`、`not`；比较：`eq`、`gte`、`lte`、`contains`。
- 所有效果先生成预览，再以单次事务提交；任何一个效果失败则整组选项回滚。

### 2.5 功能开关与模块注册

每个可选系统通过功能开关启用，例如 `feature_weather_fronts`、`feature_breeding`、`feature_orchards`。模块必须声明：

1. 依赖的系统与最低版本。
2. 新增的状态命名空间。
3. 订阅的生命周期钩子，如 `on_day_start`、`on_harvest`。
4. 存档迁移和卸载后的降级行为。
5. 数据验证规则及冲突优先级。

### 2.6 确定性随机数

随机结果使用独立随机流：

`roll = Hash(save_seed, system_id, farm_date, entity_id, roll_index)`

这样事件抽取、动物生产和品质波动互不影响；改变操作顺序不会刷新结果。每次结果记录随机流键和最终值，便于复现缺陷。测试存档可以固定 `save_seed`。

### 2.7 扩展性验收标准

- 仅新增配置即可加入一种标准作物、一种标准天气和一个普通事件。
- 任一内容配置引用不存在的 ID 时，构建检查必须失败并指出路径。
- 关闭后续模块后，旧存档仍能打开；无法识别的模块状态保留在独立命名空间，不污染核心状态。
- 数值表、事件表和本地化表均可单独热加载到开发环境。

## 3. 初始状态与全局约定（P0）

### 3.1 新存档初始状态

| 项目 | 初始值 | 设计目的 |
|---|---:|---|
| 牧场日期 | 第1年·春季·第1日 | 从春季教学开始 |
| 资金 | 2,400 G | 可承担一个季节基础运营，仍需经营 |
| 每日工时上限 | 12 WP | 约代表6小时有效劳动，不等于现实游玩时间 |
| 专注指令槽 | 3个/日 | 限制高层决定数量，减少操作负担 |
| A田区 | 12格、肥力60、湿度60 | 唯一已开垦田区 |
| B田区 | 未开垦 | 第一个扩建目标 |
| 种子 | 芜菁种子×12 | 保证首轮种植不需额外购买 |
| 鸡舍 | 1级、容量4 | 可立即体验牧场系统 |
| 动物 | 成年母鸡×3 | 健康90、心情70、亲密20 |
| 饲料 | 42份 | 足够3只鸡14天，覆盖短期离线 |
| 仓库 | 120容量单位 | 覆盖开局至少一周产出 |
| 技能 | 全部0级、0经验 | 成长从实际行为开始 |
| 日维护费 | 20 G | 回收少量货币，不形成强压 |

### 3.2 数值与舍入约定

- 金额最终取整数 G，使用“四舍五入到最近整数”；交易界面先显示最终金额再确认。
- 状态值范围默认为0—100，公式结算后统一 `clamp`。
- 数量的期望小数使用确定性随机舍入：整数部分必得，小数部分用该实体随机流决定是否 +1。
- 百分比先以小数相乘，最后一步舍入；中间结果保留至少4位小数。
- 同类加成先相加、异类乘区相乘。价格乘区顺序固定为：基础价×品质×市场×数量×渠道。

### 3.3 不可逆与保护规则

- 没有因离线直接触发的动物永久死亡、角色永久离开或主线永久失败。
- 玩家主动出售动物、拆除建筑、放弃唯一物品前必须二次确认。
- 任何日结以事务执行；失败时回滚到日结前快照。
- 至少保留最近7个牧场日的自动恢复点。

## 4. 时间与日历系统（P0）

### 4.1 压缩历法

- 每1个现实日对应1个牧场日。
- 每季21日，每年84日；春、夏、秋、冬依次循环。
- 存档创建时选择时区并锁定。默认刷新点为当地时间05:00，可在创建存档时改为00:00—08:00的整点。
- 同一现实日可分多次进入；日期只推进一次，生产与日报不得重复结算。

### 4.2 每日结算顺序

| 顺序 | 阶段 | 关键输出 |
|---:|---|---|
| 1 | 时间校验与事务锁 | 确认应结算的牧场日范围 |
| 2 | 执行未登录日托管计划 | 工时、饲料、播种与出售决定 |
| 3 | 天气和环境更新 | 湿度、天气压力、区域状态 |
| 4 | 农田更新 | 生长、健康、虫害、成熟状态 |
| 5 | 动物更新 | 喂养、健康、心情、生产、疾病 |
| 6 | 加工与建设推进 | 批次完成、工程进度 |
| 7 | 库存老化与费用 | 保质期、维护费、自动采购 |
| 8 | 销售与订单结算 | 资金、市场销量、订单结果 |
| 9 | 事件导演生成今日内容 | 待办、事件、信件、预警 |
| 10 | 写入日报与自动存档 | 可复现日志、日初快照 |

### 4.3 同日操作规则

- 基础日程在玩家第一次打开今日页面时预演，玩家确认后立即扣除资源和工时。
- 玩家未打开时，由当前托管模板在次日结算前执行。
- 播种、浇水和治疗当日生效；生长、动物生产和加工完成在下一次日结体现。
- 当日重复打开只读取同一份状态；每条命令带 `action_id`，服务层/本地规则层保证幂等。

### 4.4 时间异常

| 异常 | 处理 |
|---|---|
| 系统时间倒退不足6小时 | 仍按上次可信时间运行，不推进日期 |
| 倒退超过6小时 | 锁定现实推进，提示恢复系统时间；允许查看和规划 |
| 系统时间突然前进1—7日 | 按离线托管逐日结算 |
| 前进超过7日 | 只模拟7日，之后进入休整冻结 |
| 夏令时变化 | 以时区日期键判断，不以24小时秒数判断 |
| 跨时区旅行 | 沿用建档时区；玩家可申请一次迁移并产生冷却 |

### 4.5 验收标准

- 连续打开、跨午夜打开、修改系统时间和崩溃重启均不能重复领取产出。
- 84次有效日期推进后准确进入第2年春季1日。
- 任意一次日结崩溃后，恢复结果与无崩溃结算完全一致。

## 5. 每日循环与工时系统（P0）

### 5.1 今日页面流程

1. 阅读昨日结算和今日天气。
2. 查看系统标出的异常与即将到期项目。
3. 确认或修改基础日程。
4. 分配最多3个专注指令。
5. 处理一个主要事件；其他事件可进入待办。
6. 随时查看结果预览、账目和明日风险。

### 5.2 工时 WP

WP 是牧场角色的劳动容量，不是限制玩家现实在线时长。开局每日12 WP；未使用的 WP 不累计、不产生惩罚。

| 工作 | WP | 是否占专注槽 | 批量规则 |
|---|---:|---|---|
| 田区例行照料 | `ceil(活跃田区照料负载总和÷2)` | 否 | 包括条件浇水与巡查 |
| 鸡/鸭舍基础照料 | 1/舍 | 否 | 同舍容量内批量执行 |
| 大型动物棚基础照料 | 1/每2只 | 否 | 向上取整 |
| 播种一个田区 | 1 | 否 | 同一种子最多12格 |
| 收获一个田区 | 1 | 否 | 成熟作物批量收获 |
| 清洁一个圈舍 | 1 | 否 | 圈舍清洁度 +35 |
| 市场/小镇事务 | 1—2 | 是 | 一条指令可处理同地点多项事务 |
| 探索一个区域 | 2 | 是 | 每日每区域最多一次 |
| 建设投入 | 1—4 | 是 | 玩家选择当日投入量 |
| 深度动物互动 | 1 | 是 | 同一动物每日最多一次 |
| 配方排产 | 1 | 是 | 一次可安排设备容量内全部批次 |

### 5.3 超载与优先级

当计划超过工时上限时不自动吞掉任务，而是显示冲突清单。默认优先级：医疗与安全 > 喂养 > 已成熟收获 > 必要灌溉 > 加工/建设 > 社交/探索。玩家可以覆盖默认顺序。

- 成熟作物有1日无损收获宽限；之后每延迟1日，健康 -5、品质分 -3。
- 基础喂养无法安排时，系统建议自动购买饲料或取消低优先级指令。
- 峰值日允许用“临时协助”事件解决，但不把雇员作为首版常驻系统。

### 5.4 内容注意力预算

事件导演每天有6点注意力预算：短异常1点、人物/经营事件2点、主线/大型事件3点。每日最多3个需要选择的事件；紧急事件最多1个/日、2个/周。除真正的医疗或灾害外，事件期限不少于3日。

### 5.5 工时扩展点

- 工具升级可降低某一类例行成本，但不得让成本低于0。
- 后续雇员、宠物、自动化设施通过提供独立 `labor_source` 接入，不直接修改每日基础值。
- 新工作声明 WP、专注槽、地点、批量键、优先级和可托管策略即可被计划器识别。

## 6. 天气系统（P1）

### 6.1 天气生成

天气按季节权重从独立随机流生成，并受连续性约束。每7日生成一个天气块；严重天气同类最多连续2日，风暴每周最多1日。

| 天气 ID | 显示名 | 降水 P | 蒸发 E | 主要影响 |
|---|---|---:|---:|---|
| weather_sunny | 晴朗 | 0 | 18 | 正常；适合放牧 |
| weather_cloudy | 多云 | 0 | 10 | 作物无额外压力 |
| weather_light_rain | 小雨 | 30 | 6 | 通常免灌溉，动物室外心情 -1 |
| weather_heavy_rain | 大雨 | 50 | 4 | 过湿风险，探索收益 -20% |
| weather_storm | 风暴 | 60 | 8 | 无防护作物健康 -8，室外动物心情 -5 |
| weather_heatwave | 高温 | 0 | 35 | 湿度低于45时作物健康额外 -5 |
| weather_fog | 雾 | 0 | 6 | 探索特殊事件权重 +20% |
| weather_snow | 小雪 | 15 | 4 | 仅冬作物正常生长 |
| weather_blizzard | 暴雪 | 35 | 8 | 冬作物健康 -5，未保温圈舍疾病风险 +3% |
| weather_cold_snap | 寒潮 | 0 | 12 | 未保温圈舍心情 -6，非耐寒作物停长 |

### 6.2 季节基础权重（合计100）

| 季节 | 晴 | 多云 | 小雨/小雪 | 大雨/暴雪 | 风暴 | 高温 | 雾 | 寒潮 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 春 | 30 | 25 | 30 | 10 | 5 | 0 | 0 | 0 |
| 夏 | 40 | 15 | 15 | 0 | 10 | 20 | 0 | 0 |
| 秋 | 30 | 30 | 25 | 0 | 5 | 0 | 10 | 0 |
| 冬 | 15 | 25 | 35 | 15 | 0 | 0 | 0 | 10 |

### 6.3 预报

- 今日天气100%准确。
- 明日预报准确率100%；第2日80%；第3日65%。不准确时只能在同类强度相邻天气间变化，例如“小雨↔多云/大雨”，不能无预警从晴天变风暴。
- 气象站升级可显示7日趋势和湿度区间，但不会完全消除风险。

### 6.4 扩展规则

新天气必须声明 `tags`、P、E、作物压力、动物风险、区域修正和可替代天气集合。后续可以增加连续天气锋、沙尘、霜冻、花粉季等，无需修改作物核心公式；作物通过耐性标签响应。

### 6.5 验收标准

- 每季权重总和必须为100；缺失天气 ID 阻止构建。
- 10,000个模拟季的实际频率应在理论频率±1.5个百分点内，连续性修正造成的偏差需有基线报告。
- 风暴与严重天气上限在任何随机种子下均不被突破。

## 7. 田区、土壤与灌溉系统（P0）

### 7.1 管理单位

一个标准田区有12个种植格，但玩家以“田区”批量操作。单个田区同一时间只种一种作物；后续混种系统可通过 `subplots` 模块扩展，不改变首版田区状态。

### 7.2 田区状态

| 字段 | 范围/类型 | 说明 |
|---|---|---|
| plot_id | 稳定字符串 | 田区唯一标识 |
| cells | 正整数，默认12 | 种植容量 |
| moisture | 0—100 | 土壤湿度 |
| fertility | 0—100 | 肥力储备 |
| weeds | 0—100 | 杂草压力 |
| crop_id | 可空 ID | 当前作物 |
| crop_health | 0—100 | 当前批次健康 |
| growth_points | 非负小数 | 有效生长进度 |
| protection_tags | ID数组 | 温室、排水、覆盖物等 |
| history_tags | ID数组 | 连作、污染、事件历史 |

### 7.3 湿度公式

`M_next = clamp(M_now + P - E - U + I, 0, 100)`

- P、E 来自天气定义。
- U 为作物耗水：低耗水3、普通5、高耗水8；空地为0。
- 若例行灌溉执行且预测结算湿度低于35，I 取使最终湿度达到65的最小值。
- 基础水井一次灌溉指令覆盖2个田区；升级后覆盖4个。

湿度35—75为舒适区；20—34或76—90为轻度压力；低于20或高于90为严重压力。

### 7.4 肥力与杂草

- 作物在每次收获时扣除配置中的田区肥力点。
- 基础肥料成本60 G/份，使一个田区肥力 +20；计算等价成本为3 G/肥力点。
- 堆肥同样 +20，不消耗资金；由圈舍每周产生的堆肥原料合成。
- 休耕每天肥力 +3，最多恢复到80。
- 杂草每天 +2；小雨/大雨额外 +1。除草使杂草 -30。杂草超过60时，作物每日健康 -2。
- 大豆和三叶草使用 `soil_restore` 标签，收获时不扣肥力，并分别恢复4和6点；肥力仍不超过100。

### 7.5 作物健康日变化

| 条件 | 健康变化 |
|---|---:|
| 湿度35—75，肥力≥20，无严重天气 | +1，最高100 |
| 湿度20—34或76—90 | -3 |
| 湿度<20或>90 | -8 |
| 肥力<20 | 额外 -3 |
| 杂草>60 | 额外 -2 |
| 风暴、热浪等 | 按天气表追加 |

各项相加后一次结算。健康低于20时作物进入濒危状态；不会因玩家未登录在7日托管期内降到10以下。

### 7.6 扩展点

果树、蜂箱、稻田和温室通过新的 `land_use_type` 接入；土壤模块只提供湿度、肥力、压力与标签，不硬编码具体作物。

## 8. 作物系统（P0/P1）

### 8.1 生命周期

`未播种 → 生长中 → 成熟 → 收获宽限 → 过熟 → 清除`

- 当日完成播种后，当日日结可获得第1个生长点。
- 健康≥40、湿度20—90且季节允许时，每日生长 +1；健康20—39时 +0.5；其他情况停长。
- 再生作物首次成熟后，使用再生周期，不重复购买种子。
- 成熟后有1日无损宽限；此后健康 -5/日、品质分 -3/日。

### 8.2 收获数量

`YieldFactor = clamp(0.70 + AvgHealth / 300, 0.70, 1.05)`

`ExpectedQty = 种植格数 × 单格基础产量 × YieldFactor`

最终数量使用确定性随机舍入。平均健康90时系数为1.00；健康60时为0.90；健康100时为1.033。

### 8.3 品质

`Q = clamp(45 + 0.5×(AvgHealth-70) + 0.2×(Fertility-50) + Care + 2×Skill + Facility - 2×SevereDays + R, 0, 100)`

- Care 为0—8，来自及时灌溉、除草和无延误收获。
- Skill 为种植技能等级0—5。
- Facility 为0—8，来自温室、优质工具等。
- SevereDays 是该批次遭遇且未被防护的严重天气日数。
- R 为确定性整数随机数 -4—+4。

| 品质 | Q区间 | 售价倍率 |
|---|---:|---:|
| 普通 | 0—59 | 1.00 |
| 优良 | 60—74 | 1.15 |
| 精品 | 75—89 | 1.40 |
| 极品 | 90—97 | 1.80 |
| 传世 | 98—100 | 2.50 |

开局标准照料的期望品质分约63，通常得到“优良”；全部经济压力验算仍按“普通”价格计算，以保留安全余量。

### 8.5 作物差异化

- 短周期作物提供现金流和订单响应能力，但播种/收获工时更高。
- 高价值作物占用种子资金、肥力和照料负载，并对恶劣天气更敏感。
- 谷物直接收益较低，但保质期长、加工链稳定。
- 回肥作物按饲料等价价值计算，不应同时按全额现金出售和全额替代饲料重复记收益。

### 8.6 作物验收标准

- 普通品质、理想条件下所有作物季净收益为正。
- 标准现金作物季净收益目标区间为1,100—2,100 G/田区；超过范围必须有明显工时、风险或用途理由。
- 健康90时产量与配置基础产量一致，误差只来自确定性随机舍入。
- 新增作物不修改作物状态机代码即可完成播种、生长、收获和销售。

## 9. 动物与圈舍系统（P0/P1）

### 9.1 个体状态

每只动物记录：ID、物种、名称、性别、年龄阶段、健康、心情、亲密、饱食、疾病、生产冷却、所在圈舍、来源和重要经历标签。

### 9.2 圈舍状态

圈舍记录容量、清洁度、保温、防风、放牧许可和升级标签。每日清洁度变化：

`Clean_next = clamp(Clean_now - (4 + 2×OccupancyRate) + CleanAction, 0, 100)`

其中清洁行动为 +35。满员圈舍每日约 -6，因此通常每5—6日需要一次批量清洁。

### 9.3 健康与心情

- 足量喂食且清洁度≥50：健康 +1、心情 +2。
- 缺食：健康 `-ceil((1-FeedRatio)×8)`，心情 -8。
- 清洁度<30：健康额外 -4。
- 圈舍超员：心情 -5，疾病概率 +2个百分点。
- 合适天气放牧：心情 +3；严重天气放牧按天气表扣减。
- 深度互动：亲密 +2—4、心情 +2；同一动物每日最多一次，每周亲密增长上限10。

### 9.4 疾病概率

`P_disease = clamp(0.002 + max(0,60-Health)×0.002 + max(0,40-Clean)×0.0015 + WeatherRisk + OvercrowdRisk, 0, 0.20)`

健康≥60、清洁≥40且无恶劣天气时，基础日风险为0.2%。疾病先进入“异常”而非直接产生永久后果；及时处理通常只造成费用和暂停生产。

### 9.5 产品产出

鸡的产蛋概率：

`P_egg = clamp(0.55 + 0.002×Health + 0.0015×Mood - IllnessPenalty - OvercrowdPenalty, 0.25, 0.95)`

健康90、心情70时为83.5%，与经济模型采用的85%接近。奶类数量以物种基础数量乘生产系数，使用确定性随机舍入。

动物产品品质：

`Q = clamp(35 + 0.25×Health + 0.15×Mood + 0.08×Affinity + 2×Skill + Facility - DiseasePenalty + R, 0, 100)`

品质区间和售价倍率与作物一致。

### 9.7 生命周期与保护

- 幼鸡7日、牛犊/羊羔14日后进入成长期；购买成体价格更高但立刻生产。
- 首版不做自然死亡。进入老年后产出 -15%，可以养老、转让或通过事件安排退役。
- 离线托管期间健康不低于40；若饲料不足则进入休整并暂停生产。
- 玩家主动忽视严重疾病时，结果是送医、费用和关系反馈，而不是突然删除动物。

### 9.8 后续繁育接口（EXT）

动物实体预留 `genome_ref`、`parent_ids` 和 `traits`，但首版不生成遗传数值。繁育模块启用后，标准生产公式只读取最终特性修正，不关心遗传算法。

## 10. 库存、保质期与物流（P1）

### 10.1 容量

- 普通仓库初始容量120单位；大多数产品1件占1单位，大型材料按配置占2—5单位。
- 种子进入独立种子柜，饲料进入容量120的料仓，不挤占产品仓库。
- 出售箱中的物品从仓库移除并锁定，次日日结到账；玩家可在当日结算前撤回。

### 10.2 保质期

| 类别 | 基础保质期 | 50%寿命后 | 80%寿命后 | 过期处理 |
|---|---:|---|---|---|
| 叶菜/浆果 | 4日 | 品质分 -5 | 品质分再 -10 | 转为堆肥原料 |
| 根茎 | 10日 | -5 | 再 -10 | 堆肥原料 |
| 谷物/种子 | 60日 | 无变化 | -5 | 低价值饲料原料 |
| 鸡蛋 | 14日 | -5 | 再 -10 | 堆肥原料 |
| 鲜奶 | 5日 | -5 | 再 -10 | 丢弃/事件用途 |
| 腌制/果酱 | 45日 | 无变化 | -5 | 丢弃 |
| 奶酪/毛线 | 60日 | 无变化 | -5 | 降为普通品质 |

### 10.3 满仓规则

产出不会静默消失。满仓时依序放入出售箱预留区、临时区（容量20、仅保留1日），仍溢出则生成必须处理的仓储异常。托管模式优先出售最早到期且不属于任务保留的物品。

### 10.4 扩展点

冷藏库、地窖和运输箱通过 `storage_modifier` 改变容量、保质期或可接受标签。物品本体只声明基础属性，不硬编码具体建筑。

## 11. 加工系统（P1）

### 11.1 排产规则

- 修复加工坊后拥有2个并行队列，每批默认1个牧场日完成。
- 每日用1个专注指令安排当日全部空闲队列，消耗1 WP。
- 原料在确认排产时锁定；取消未开始批次全额返还，已开始批次返还80%原料等价值。
- 加工品质以输入品质加权平均为基础，再加技能和设备修正；不得通过混入一个极品原料把整批无成本提升为极品。

配方配置声明输入、替代输入、输出、设备标签、耗时、操作成本、品质传递规则和解锁条件。新设备只提供队列和修正，不重写库存事务。

## 12. 经济、市场与订单（P0/P1）

### 12.1 售价公式

`FinalPrice = round(BasePrice × QualityMul × WeeklyMarketMul × VolumeMul × ChannelMul)`

- WeeklyMarketMul 从0.90、0.95、1.00、1.05、1.10中按10%、20%、40%、20%、10%权重确定，数学期望为1.00。
- VolumeMul 按同一物品当周累计出售量计算：1—20件为1.00；21—50件为0.90；51件以上为0.80。
- 普通出售的 ChannelMul=1.00；订单为1.15—1.35；剧情援助可能低于或高于市场，但必须明确提示。
- 数量分档逐段计算，不能因第21件而把前20件一起降价。

### 12.2 现金流保护

- 日维护费20 G，于日结扣除。
- 饲料库存不足3日时提示；托管可按市场价自动补到7日储备，金额不超过当前现金的30%。
- 资金不足不会立刻失败。系统先停止非必要加工和建设，再提供一次7日低息周转事件；首版不累计复利债务。
- 订单不要求玩家交付唯一剧情物品；自动保留物品不会被托管出售。

### 12.3 订单

订单字段包括物品标签、数量、最低品质、期限、奖励倍率、发布者和后续标记。普通订单期限3—7日；每周同时存在不超过3个。放弃订单只影响发布者信任或短期冷却，不扣除额外资金。

### 12.4 市场反馈

每周一生成价格趋势，周日结算销量并更新下一周权重。玩家可以看到基础价、当前倍率、数量折扣和预计到账，避免隐藏扣减。

### 12.5 经济扩展点

餐馆合同、批发商、节日摊位等作为新 `sales_channel` 接入。渠道可以修改倍率、容量、结算周期和关系效果，但不能绕过库存扣除和交易日志。

## 13. 建筑与牧场扩建（P1）

### 13.1 建设规则

- 确认工程时锁定全额资金；每天通过一个专注指令投入1—4 WP。
- 工程达到所需 WP 后于次日日结启用，避免同日反复利用容量变化。
- 未开工取消全额返还；已开工按未完成比例返还资金的80%，并写入日志。
- 同时最多进行2个工程，避免计划页面过载。

### 13.3 选择节奏

首季保守结余约1,405—2,284 G，加上初始现金后，玩家通常只能在首季末完成一项中型扩建，形成“扩田、加工或继续储蓄修畜棚”的选择。

### 13.4 扩展点

建筑效果通过 `capability` 提供，例如 `storage.capacity +120`、`processing.queue +2`。新建筑不得直接修改其他系统私有字段。

## 14. 玩家技能与解锁（P1）

### 14.1 技能

种植、饲养、加工、经营、采集、交往共6项，等级0—5。累计经验阈值：0、30、80、150、240、350。

| 技能 | 主要经验来源 | 每级稳定收益 | 关键解锁示例 |
|---|---|---|---|
| 种植 | 每田区收获6 XP、农业事件2 XP | 作物品质分 +2 | L2预判虫害，L4高级轮作 |
| 饲养 | 每圈舍完成一日照料1 XP、医疗3 XP | 产品品质分 +2；疾病风险 -0.1个百分点 | L2行为判断，L4繁育接口 |
| 加工 | 每完成批次1 XP、新配方3 XP | 操作成本 -2%，最多 -10% | L2第二类设备，L4批量配方 |

- 技能主要提高信息质量、品质和选择，不直接大幅提高基础产量。

- 等级5后继续累计“熟练记录”但不再无限增加倍率。

## 15. 小镇与人物关系（P1/P2）

熟悉度不能替代信任。普通聊天主要增加熟悉，兑现承诺和关键选择改变信任。

## 16. 事件导演与内容系统（P0/P1）

### 16.1 事件数据结构

每个事件至少包含：事件 ID、schema 版本、类别、标签、触发条件、基础权重、冷却、互斥组、注意力成本、期限、正文键、选项、效果、后续事件和回归摘要模板。

### 16.2 选取算法

1. 过滤条件不满足、冷却中、互斥冲突的事件。
2. 计算权重：基础权重×季节×天气×状态紧迫度×近期重复衰减。
3. 先选紧急槽，再选主线/人物槽，最后用短事件填充注意力预算。
4. 同标签事件7日内重复时权重×0.25；完全相同事件在冷却结束前不得重复。
5. 若没有合格事件，生成无选择的生活日志，不强行制造问题。

### 16.3 事件类型与数量目标

| 类型 | 正式版目标 | 单次阅读量 | 常见期限 |
|---|---:|---:|---:|
| 农田/经营 | 40 | 100—350字 | 3—5日 |
| 动物 | 35 | 150—500字 | 医疗1日，其余3日 |
| 天气/环境 | 32 | 100—400字 | 1—4日 |
| 居民关系 | 48 | 300—900字 | 5—7日或无期限 |
| 主线 | 16 | 600—1,200字 | 通常无硬期限 |
| 节日/季节 | 12 | 400—1,000字 | 7日窗口 |
| 合计 | 183 | — | — |

### 16.4 延迟结果

事件选项可安排 `scheduled_effect`，在未来日期或条件满足时触发。延迟结果必须在日志中说明它源自哪个选择；重要结果不得没有因果提示。

### 16.5 示例事件

**事件：** `event_cow_bloat_01`  
**条件：** 拥有奶牛；健康≥40；近30日未触发；非托管冻结。  
**注意力：** 3；**期限：** 当日；**紧急：** 是。  
**描述：** 奶牛停止进食并反复踢向腹部。  

| 选项 | 条件/成本 | 即时效果 | 延迟效果 |
|---|---|---|---|
| 联系兽医 | 320 G | 健康 +15、信任 +1 | 3日内生产 -10% |
| 自行检查 | 饲养技能≥2 | 80%正确处理；20%次日转兽医 | 成功得3 XP，失败多付120 G |
| 暂时观察 | 无 | 健康 -8 | 次日70%加重，30%自行缓解 |

### 16.6 内容扩展验收

- 新事件只用白名单条件/效果即可完成常规分支和延迟结果。
- 事件引用的文本键、物品 ID、居民 ID 和后续 ID 必须通过静态检查。
- 每个选择至少有一条玩家可理解的即时或延迟反馈。
- 自动测试10,000日不得出现紧急事件超过每周上限或互斥事件并存。

## 17. 探索与采集（P2）

### 17.1 目标

为每日30—60分钟提供可选内容，不制造必须反复点击的采集小游戏。

### 17.2 规则

- 探索消耗2 WP和1个专注槽，每区域每日最多一次。
- 基础产出2—4件，受季节、天气、采集技能和区域状态影响。
- 事件触发基础概率30%；同一区域连续3次后稀有事件权重降低，鼓励轮换。
- 采集品主要用于配方、委托和故事；直接出售收益目标不超过同等工时农业收益的80%。

### 17.3 区域

森林提供草药、菌类和木料；河岸提供水生材料和天气线索；旧车站提供主线档案。后续钓鱼、矿洞可作为区域专属 `activity_module` 接入。

## 18. 日志、周报与长期记忆（P1）

### 18.1 日志分层

- 账务日志：每笔资金、物品和价格构成。
- 经营日志：播种、收获、生产、建设和异常。
- 生活日志：动物行为、居民来信、天气感受。
- 决策日志：事件选项、即时效果、待触发后果。

### 18.2 周报

每7日汇总收入、支出、净现金流、工时利用率、滞销品、即将成熟作物、动物风险、关系变化和下周天气趋势。周报只提示，不替玩家自动改变战略。

### 18.3 年度报告

年度报告由固定统计字段和叙事模板组合，至少包含：总收入、净收益、主要产品、土地利用、动物福利、居民关系、关键选择、未完成目标和下一年建议。叙事模板按玩家行为标签选择，禁止用单一“善恶值”概括玩家。

### 18.4 记忆接口

重要日志保存 `subject_ids`、`event_id`、`choice_id` 和情绪/主题标签。后续事件按标签引用自然语言模板，使居民能提及旧选择而不复制整段文本。

## 19. 离线托管与回归（P0）

### 19.1 托管阶段

| 未登录时间 | 行为 | 保护 |
|---|---|---|
| 1—3日 | 正常执行基础日程，继续既有种植和生产 | 不自动接受新订单、不使用保留物品 |
| 4—7日 | 切换保守策略：不播种高风险作物，优先出售易腐品、补充饲料 | 健康不低于40，暂停高风险探索 |
| 超过7日 | 只模拟前7日，之后牧场休整冻结 | 不再消耗、不再生产、不生成逾期惩罚 |

### 19.2 托管优先级

医疗 > 喂养 > 收获成熟作物 > 必要灌溉 > 易腐出售 > 既有加工 > 其他。托管不得主动出售动物、启动建筑、消耗稀有道具或做主要剧情选择。

### 19.3 回归报告

报告显示模拟天数、执行计划、收入支出、状态变化、待办和进入休整的日期。玩家可以逐日展开，但默认只显示摘要，避免回归时信息爆炸。

### 19.4 初始储备验证

42份饲料可供3只鸡14日；离线只模拟7日，最多消耗21份。7日维护费140 G。即使没有任何产出，初始资金也足以覆盖保护周期。

## 20. 纯文字界面与交互（P0/P1）

### 20.1 页面结构

主导航：今日、田区、动物、仓库、加工、市场、小镇、待办、日志、设置。默认进入“今日”。

### 20.2 视觉与办公场景规则

- 不加载图片资源，不出现角色头像、作物图标或动态背景。
- 默认静音，无自动播放音频；声音模块首版不初始化。
- 使用系统字体、低饱和灰阶、有限的状态色，并提供完全灰阶模式。
- 支持紧凑视图：一屏显示日期、资金、风险、工作计划和待办。
- 浏览器标签标题可自定义；提供一键切换到“本周经营摘要”的快捷键。
- 不用闪烁、弹跳、倒计时红点和全屏奖励动画制造注意力压力。

### 21.2 迁移原则

1. 每次只做相邻版本迁移，例如1→2→3，不写跨多个版本的巨大迁移器。
2. 迁移前自动备份；迁移失败则保留原文件并进入只读恢复模式。
3. 新增字段必须有确定默认值或可由旧状态推导。
4. 内容被弃用时，用映射表替代；无法映射的库存转为等价值通用物资并明确记录。
5. 模块状态独立迁移，不允许一个可选模块重写核心存档版本。

- 自动保存采用临时文件写完后原子替换。
- 支持导出单文件备份；导入先校验校验和、版本和必需字段。
- 默认保留最近7日自动存档、4个周存档和1个年初存档。

## 22. 数值平衡与验算（P0）

### 22.1 作物公式复算

非再生作物的理想季净收益：

`Net = 收获次数×12×单格产量×基础售价 - 收获次数×12×种价 - 收获次数×肥力消耗×3`

再生作物只购买一次种子。所有作物计算结果均为正；现金作物落在1,104—2,076 G/田区，南瓜2,070、土豆2,061、甜瓜2,076处于高端，但分别承担长周期、高本金或天气风险。三叶草按饲料等价值而非现金计算。

### 22.2 首季现金流

基准假设：开局3只鸡；21日；芜菁连续5轮；首轮12粒种子赠送；普通品质；市场倍率1.00；不加工、不扩建。

| 项目 | 基准情景 | 压力情景 |
|---|---:|---:|
| 初始现金 | 2,400.00 | 2,400.00 |
| 作物销售收入 | 2,880.00 | 2,304.00（产量-20%） |
| 鸡蛋收入 | 1,713.60（85%产蛋） | 1,411.20（70%产蛋） |
| 后4轮种子 | -1,200.00 | -1,200.00 |
| 肥力补充等价成本 | -60.00 | -60.00 |
| 饲料成本 | -630.00 | -630.00 |
| 日维护费 | -420.00 | -420.00 |
| 季末现金 | 4,683.60 | 3,805.20 |
| 净变化 | +2,283.60 | +1,405.20 |

压力情景仍保留1,405 G正现金流，且没有计入通常会出现的优良品质溢价，说明开局不会因普通天气波动陷入不可恢复负债。

### 22.3 极端安全检查

- 若首季作物完全无收入，鸡按85%产蛋：季末现金仍为3,063.60 G（鸡蛋1,713.60 - 饲料630 - 维护420）。
- 若首季鸡完全无产出且作物也失败：支出仅饲料630、维护420，季末仍有1,350 G；同时实际系统会提前触发保守托管和经营援助。
- 因此首季没有“随机性导致必败”的路径，真正损失主要来自玩家明确选择。

### 22.4 动物与建筑回本

动物单体回本为34.9—66.9日。计入建筑后的典型投资：

| 投资 | 总成本 | 新增日净收益 | 理论回本 |
|---|---:|---:|---:|
| 鸡舍扩建＋4只鸡 | 4,200 | 68.80 | 61.0日 |
| 畜棚修复＋1头奶牛 | 8,300 | 118.50 | 70.0日 |
| 加工坊满负荷（平均增值24 G×2批/日） | 2,800 | 48.00 | 58.3日 |
| 加工坊半负荷（平均25 G×1批/日） | 2,800 | 25.00 | 112.0日 |

建筑选择不存在十日内无脑回本；扩田回本较快，是预期的新手第一升级，但会同步增加工时、种子占用和仓储压力。

### 22.5 每日工时负载

| 阶段 | 田区例行 | 动物例行 | 播种/收获均值 | 专注任务 | 合计/上限 | 利用率 |
|---|---:|---:|---:|---:|---:|---:|
| 开局 | 1 | 1 | 0.5 | 4 | 6.5/12 | 54.2% |
| 中期常态 | 2 | 2 | 1.5 | 4 | 9.5/12 | 79.2% |
| 中期峰值 | 2 | 2 | 4 | 4 | 12/12 | 100.0% |
| 后期常态（升级后） | 3 | 3 | 2 | 3 | 11/14 | 78.6% |

常态目标为50%—80%；100%只允许短期峰值。多个田区同日成熟会造成峰值，因此系统必须显示未来3日工时预测，并允许错峰播种。

### 22.6 仓储与离线容量

- 开局每周鸡蛋期望约17.85件；一次田区收获约12件；即使再采集14件，一周新增也约44件，低于120容量。
- 饲料存放在独立料仓，不与产品争抢容量。
- 离线7日最多消耗21份鸡饲料和140 G维护费，均低于初始储备。

### 22.7 自动验算门槛

每次数值表变更必须运行以下断言：

1. 所有作物在普通品质和理想条件下季净收益>0。
2. 首季压力情景季末现金≥3,500 G。
3. 所有基础动物扣饲料后的期望日净收益>0，单体回本30—75日。
4. 所有加工配方普通品质下增值>0，但单批增值率不高于35%。
5. 定义的常态工时场景不超过上限；峰值场景最多等于上限。
6. 市场倍率分布期望严格等于1.00。
7. 任一数量、价格、概率、状态公式不得产生NaN、负库存或越界状态。

## 23. 内容迭代与扩展路线

### 23.1 迭代原则

- 每次迭代至少扩展“一个可见内容面”和“一个复用能力”，例如加入霜冻事件时，同时完善天气标签条件，而不是只写单个硬编码剧情。
- 新功能默认从关闭的功能开关开始，先在测试存档启用。
- 旧系统只通过公开命令和钩子被扩展，避免后续功能直接改写核心结算顺序。
- 先扩展内容密度，再扩展系统数量；保证每日循环稳定后再加入遗传、雇员等高耦合模块。

### 23.2 分阶段内容

| 阶段 | 可玩范围 | 主要系统 | 内容规模 | 验证目标 |
|---|---|---|---|---|
| 技术原型 | 7个牧场日 | 日期、田区、鸡、工时、存档 | 3作物、8事件 | 日结幂等与核心循环 |
| 春季体验版 | 21日 | 天气、市场、加工、4居民、托管 | 6作物、鸡、40—60事件 | 玩家是否愿意持续一个现实月 |
| 四季Alpha | 84日 | 全季节、5动物、8居民、建设 | 19作物、120事件 | 经济和工时长期稳定 |
| 内容Beta | 84日可循环 | 周报、年报、完整主线与事件导演 | 183事件、8配方 | 重复率、叙事反馈和回归体验 |
| 后续迭代 | 按模块上线 | 新天气、果树、蜂箱、繁育、雇员等 | 每批独立内容包 | 旧存档兼容与模块价值 |

### 23.4 兼容性发布清单

- 新配置通过静态验证和10,000日模拟。
- 旧存档复制后完成迁移、加载、推进7日、导出与再次导入。
- 关闭新功能开关后，核心日结结果与旧版本基线一致。
- 新事件在注意力预算内，不提高紧急事件周上限。
- 新经济内容不能使既有基础商品失去用途或形成无成本循环。

## 24. 开发实施与验收

### 24.1 模块开发顺序

1. 状态模型、确定性随机数、事务日志和存档。
2. 日历、日结、工时计划与离线托管。
3. 田区、作物、库存和出售闭环。
4. 动物、圈舍、产品与异常。
5. 天气、事件导演和待办。
6. 加工、订单、建筑和技能。
7. 居民关系、主线、周报与年报。
8. 内容工具、批量验证、性能与可访问性。

### 24.2 技术原型完成定义

- 可创建存档并连续推进7个现实/模拟牧场日。
- 芜菁播种、照料、成熟、收获、出售和再次购买种子的资金闭环正确。
- 3只鸡能消耗饲料、产蛋、改变状态并生成日报。
- 每日工时和3个专注槽不会被重复消费。
- 退出、崩溃恢复、跨日和离线3日的结果可复现。
- 至少8个事件使用数据配置运行，无硬编码中文条件。
- 数值自动验算全部通过。

### 24.3 春季体验版完成定义

- 21日春季完整可玩，正常玩家每日核心操作不超过15分钟。
- 6种春季作物、鸡、4名居民、市场、加工坊和至少40个事件可用。
- 玩家连续缺席7日后回归，农场没有永久性不可逆损失。
- 20名测试者中，至少80%能在不阅读外部说明的情况下完成首次播种、出售和工作调整。
- 同一测试种子在相同命令序列下产生完全一致的结果与日志哈希。

### 24.4 平衡测试矩阵

| 测试角色 | 主要行为 | 观察指标 |
|---|---|---|
| 保守经营者 | 只种低风险作物、少扩建 | 是否仍有稳定成长目标 |
| 最大收益者 | 计算最优作物与加工 | 是否出现单一压倒性策略 |
| 动物偏好者 | 少种植、多养殖 | 饲料、建筑和现金流是否自洽 |
| 剧情玩家 | 经常社交探索、低工时经营 | 是否会因内容选择陷入破产 |
| 低频玩家 | 每3—7日上线 | 回归信息量和托管结果是否可接受 |
| 极端遗漏者 | 不处理异常、不调整计划 | 是否有反馈但不造成突然删档式惩罚 |

## 附录 B：必测边界案例
